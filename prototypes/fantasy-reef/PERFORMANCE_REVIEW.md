# 性能检查与本地优化

2026-11-15（Asia/Shanghai）。对照本地提交 `85180cd`；修改仅针对当前实际使用的 `prototypes/fantasy-reef/`。原根页面是早期 p5 版本，不能拿它与新美术版本直接比较 FPS。未提交、未 Push、未修改 Pages 工作流。

## 定位结果与证据边界

当前渲染为 **Canvas 2D 场景合成 + WebGL 贴图网格形变**，不是完整 3D。六张 PNG 仅初次上传 GPU；背景已有缓存。主画布 DPR 上限桌面 1.5、窄屏 1.4，桌面像素数是逻辑分辨率的 2.25 倍。该上限本轮保持不变。

1. **实测主要瓶颈在渲染路径**：每条鱼、每只水母和每片近景珊瑚原来都清理同一个 1024² WebGL 表面、绘制，再立即交给 Canvas 2D。N 条鱼时每帧有 N+4 次写入/读取交错，容易让浏览器反复提交或解析 GPU 表面。Safari 同条件 25 鱼时，原绘制提交平均 81.96ms，CPU 更新仅 0.083ms；优化后绘制提交为 2.71ms。调用序列及主线程绘制成本均已确认，内部 GPU 等待/拷贝的精细占比尚未单独剖析，不能把提交时长直接称为纯 GPU 时长。
2. **已确认的慢放原因**：原 `app.js` 把 dt 限制在 40ms。实际低于 25FPS 时丢弃经过的时间，鱼身、鱼鳍、水母、粒子和追食一起慢放。它与鱼种本来游得慢是不同问题；礁鱼/灯鱼/神仙鱼速度参数 31/45/22 保留。
3. **Boids 的重复工作**：N² 遍历先对所有邻居调用 `Math.hypot`，即使远离感知范围；每只灯鱼重复创建三个相同的漂移中心、计算三角函数；每次更新重新创建 motion 对象与邻居字段数组。50 条鱼的独立 CPU 更新中位数原本不到 1ms，证据不支持把全部卡顿归因于 Boids。此次保留原遍历顺序与力学公式，未引入空间哈希或改变邻居集。
4. **其他成本**：每帧重新排序固定深度的鱼，创建水母/珊瑚布局对象、约 10 个径向渐变（无投喂时）及 4 个动态光束线性渐变。水母、珊瑚和鱼共用 40×56 连续网格；透明叠加与两层昼夜背景也有成本。本轮保留网格、全部贴图、环境数量、透明度和光束。不存在每帧 CSS/Canvas blur 调用；界面原有 CSS 背景模糊保留，实际页面 HUD 会计入其整体帧间隔。

## 修改

- `warp.js`：先批量绘制形变贴图到动态图集，再按原顺序合成到 Canvas。按纹理分组绑定，图集布局只在数量或尺寸变化时重算；一个清屏，写入后统一读取。各贴图有效分辨率、32px 留边、着色器源、形变时间与所有 uniform 保持原样；GPU 不支持时保留 Canvas 降级，图集超过设备上限时回退逐张路径。
- `scene.js`：缓存光晕纹理、鱼的固定深度顺序、海葵方向和珊瑚布局；复用两个水母对象与绘制指令。保留 75 个浮游微粒、最多 80 个互动粒子及全部原动画路径，未删除特效。
- `fish-school.js`：远邻先做平方距离筛选，只有可能参与作用的邻居才求精确距离；三个鱼群中心每个模拟步只计算一次；复用 motion/快照对象。不改变近邻求和顺序、速度、转向、追食目标保持、鱼种比例、活动范围。
- `timing.js` / `app.js`：按真实经过时间以不大于约 1/60 秒的小步推进，修复普通低帧率慢放。单帧最多推进 250ms，防止极端阻塞后失控；丢弃量由面板/JSON 记录。切后台和暂停仍冻结，不追补离开期间的时间。
- `performance.js` / `perf/`：按需面板、同条件浏览器测试和基线副本。无远程遥测。基线三个脚本从 `85180cd` 逐字节提取，普通页面不加载它们。
- `build:study` / `preview:study`：仅用于本地对比的静态产物。保留 `npm start` 与默认生产构建，不改变部署内容。

## 已取得的测量

### 实际浏览器同条件测试

Safari 最初被自动化环境视为后台；用户保持前台后，六组真实测试全部完成并通过浏览器下载导出。原始完整结果保存在 [perf/browser-results.json](perf/browser-results.json)，测量时间为 2026-11-15 00:31（Asia/Shanghai），Apple M1 本机 Safari 27.0 / WebGL。固定逻辑 1280×720、DPR 1.5、画布 1920×1080，初始种子与素材一致；每组预热 3 秒、采样约 12 秒，优化前/后交替，全部在前台、无后台作废组。

| 鱼数 | FPS 前 → 后 | 平均帧间隔 ms 前 → 后 | p95 帧间隔 ms 前 → 后 | 绘制提交 ms 前 → 后 |
| --- | ---: | ---: | ---: | ---: |
| 10 | 24.27 → 60.00 | 41.21 → 16.67 | 49 → 18 | 39.90 → 2.55 |
| 25 | 11.99 → 60.01 | 83.39 → 16.66 | 94 → 18 | 81.96 → 2.71 |
| 50 | 6.47 → 60.00 | 154.66 → 16.67 | 167 → 18 | 151.63 → 2.76 |

对应浏览器更新平均耗时为 0.062→0.018、0.083→0.039、0.152→0.094ms；与独立 Node 测试不同，浏览器 JIT、计时精度与积分步数也不同，不能横向混比。优化后 10/25/50 鱼超过 25ms 的帧为 0/2/0；每组约 721 帧。原时间推进分别为实际经过时间的 94.7% / 48.0% / 25.9%，优化后均为 100%，没有触发 250ms 极端截断。这实际区分并验证了“掉帧”与“掉帧引发慢放”两种问题。

实际完整页面 HUD 另多次读到 **30 条鱼、2160×1230 主画布、WebGL atlas，约 1 秒采样 59.9–60.0FPS、p95 17–18ms、时间推进 100%**，并检查投喂与数量调整。六组测试覆盖当前机器和约 12 秒的单组窗口，不能据此承诺所有硬件或长时间负载都稳定 60FPS；未取得实体手机 FPS。

可复测的浏览器工具在 [perf/index.html](http://127.0.0.1:5173/prototypes/fantasy-reef/perf/index.html)：固定逻辑 1280×720、DPR 1.5、画布 1920×1080。依次运行 10/25/50 的原版与优化版，每组 3 秒预热 +12 秒采样。显示实际 rAF FPS、帧间隔 p50/p95/p99、更新、绘制提交、长帧、时间推进与后端，并可下载 JSON。进入后台会使采样无效；绘制提交耗时不等于独立 GPU 执行时长。此对照隔离场景内核，不包含主页面界面模糊；主页面 `?perf=1` 用来观察完整合成。

开发服务器就是静态文件服务，没有热更新或开发版渲染依赖。`study-dist` 的 21 个运行文件与源文件逐字节一致；开发/静态产物预览的 22 个场景及共享文件 HTTP 200、响应内容相同。可以在 `PORT=5174 npm run preview:study` 地址重复完全相同的六组测试。上述六组来自开发地址，未额外取得独立生产地址的 FPS 对照，因此不声称构建本身能加速运行。

## 行为、画质与功能验证

- 10/25/50 各 1200 个固定步，逐鱼比较 x/y、速度、航向、转弯、摆尾相位、群组和食物消耗，与基线数值完全一致。原有 9 组桌面/窄屏/数量、追食、分离、平滑转向与增减数量检查通过。
- 合成 3 秒、速度 31px/s 的时间测试：60/30Hz 原新均前进 93px；20Hz 原 74.4px、新 93px；10Hz 原 37.2px、新 93px。**这些是合成时间推进测试，不是设备测得 FPS。** 修复会让低帧率下运动恢复应有速度，不是提高鱼种游速。
- 着色器字符串、uniform、目标位置、每张分辨率与图集不重叠检查通过，数量/尺寸变更可重建；本机 Safari 完整场景、增减鱼、暂停/恢复、主题和沉浸开关已检查，持续动态和食物消耗另由行为测试验证。
- 六张素材未改，背景缓存像素完全一致。原生 Canvas 降级帧对比 25/50 鱼、昼夜和桌面/窄屏，平均 RGB 通道绝对差 0.023–0.049/255、最大 4/255，来源为光晕栅格缓存的插值与量化；不是降低素材清晰度。见 [perf/visual-results.json](perf/visual-results.json)。此像素数据不覆盖真实 WebGL 逐像素一致性，Safari 已人工检查合成外观。
- `npm run build:study`、原生产行为检查、运行文件引用和 HTTP 校验通过；没有新增 npm 依赖、外部 API、发布步骤。

未降低鱼数、粒子数、素材质量、DPR 或网格精度，未删除既有功能。主要变化是批量渲染、缓存、去除重复计算以及修正慢放时钟。本机三种压力场景已达到约 60FPS，未来可用同一工具复测其他设备或后续迭代。
